## Method

Three tiers, because a suite nobody can afford to run is not a gate: `retrieval` calls no model, `single_turn` runs the real model against staged tools, `agent_run` runs the whole loop against a real repository.

Scoring reads the trace, not the prose — tool sequence as an ordered subsequence, arguments re-validated against each tool's own schema, citations, refusal, and 14 forbidden behaviours. Twelve have a deterministic detector; two do not and are reported **unchecked** rather than absent.

**Every threshold reads the lower bound of a range.** The same case here has scored 0.00 and 1.00 on consecutive passes, so a median is a draw quoted as a promise.

## Failure modes

22 tracked in [`failure-modes.csv`](../evals/failure-modes.csv). `make modes CHECK=1` runs in CI and refuses a mode marked closed without a test that exists.

| Status | Count | |
|---|---|---|
| closed | 10 | F1–F5, F15, F19–F22 — each names the test pinning it |
| known | 3 | F11, F12, F13 — real, accepted, case tagged `known-failure` |
| open | 9 | F6–F10, F14, F16–F18 |

**The two that are the agent's, not the instrument's:**

**F9 — answers from parametric memory after declaring the question out of domain.** Asked for the boiling point of tungsten it wrote that this has no connection to any tool domain, then answered anyway, with the right number. Correct-by-luck is indistinguishable from hallucination downstream. Mitigation: `GROUNDING` must bind the refusal it already states. Not done.

**F10 — answers about the target repository using this project's own spec.** Asked what conventions the target repo follows, it searched the corpus, retrieved our `SPEC`, and offered `POST /v1/run` as the answer. Two defects stacked: a checkout question routed to the corpus, then grounded in a source about something else. Case `tool-011`, reproducible on demand.

**F14 — the harness's own stub receipts are too thin to ground an answer.** `{"recorded": true}` cannot support "I inserted the line at line 0 of CHANGELOG.md", and the judge scores those cases 5, 2, 5, 5, 5 across passes — the thin receipt does not make the judge wrong, it makes the question undecidable. Mitigation: return real receipts. Not done.

## Drift

`make drift` compares a run to `results/baseline.json`.

A rate drop counts **only when the two ranges do not overlap**. Composition is tracked separately: a failure mode appearing where there was none, or a case flipping verdict, regardless of the aggregate.

That second half earned its place on the first real comparison. Two consecutive runs, same model, same commit: **the pass rate did not move and two cases flipped to failing while two flipped to passing**, with a new failure mode appearing. An aggregate can hold perfectly still while the set of things failing turns over completely.

## Known limitations

- **No production traffic.** The promotion path runs from the golden set and the replay corpus. There is no online capture, so `--from-run` promotes from evals, not from users. Calling that a production pipeline would be a diagram of one.
- **Two behaviours have no detector** — `invent_figure`, `fabricate_tool_result` — named in `gates.yaml` under `unscored_risk` with their compensating controls. The judge that could carry them sits at κ 0.651–0.823 and errs toward passing invented content, which is the wrong direction for exactly these two.
- **CI cannot run the agent.** It retrieves against a committed corpus and replays 48 frozen runs; a regression in agent behaviour has no CI signal. Closing that needs the target checkout in a runner, which is a bigger change than it sounds.
- **Three of five `agent_run` cases have no replay trace**, so the tier that proves the product end to end is two-fifths covered.
- **`mean_faithfulness` is only measured when `JUDGE=1`**, and is never gated.

## What I would do next

1. **Return real receipts from the staged write tools.** It closes F14, and it unblocks judging the write cases at all — today their verdict is a coin flip because there is nothing to decide against.
2. **Bind the refusal in `GROUNDING`** so F9 cannot state that a question is out of domain and then answer it.
3. **Build the detector for `invent_figure`**: a number in an answer that appears in no tool result is mechanically checkable, and it is the larger half of the remaining unscored risk.
